# 영끌문S 설계서

> 게임성을 넣은 모의 트레이딩 게임. 완전 오프라인, 노트북 1대, 한 번에 플레이어 1명.
> 숫자는 `npm run sim`(= `node scripts/simulate.ts`) 출력이다(4장, 따로 잰 값은 그 자리에 적었다). 조정값은 `src/config.ts` 한 곳에 있고, 앱과 시뮬레이션이 같은 값을 읽는다.

## 0. 한눈에 보기

- **화면:** 좌측 종목 탭 5개(**난이도 쉬운 순**)와 선택한 종목의 상세 설명, 가운데 선택한 종목의 캔들(막대) 차트, 우측 계좌·**매수 / 인버스 / 매도**·보유 종목.
- **차트:** 캔들 하나가 **3초**(0.1초 틱 30개). 보조 지표는 없다. 차트를 **마우스로 누른 채 끌어** 캔들 크기를 바꾼다. 좌우로 끌면 폭(화면에 캔들 20~300개, 처음 100개 = 5분), 위아래로 끌면 높이(0.3~5배)가 바뀐다. **오른쪽 버튼을 누른 채 끌면** 차트를 잡아 옮기듯 화면이 움직인다: 좌우로 지난 캔들을 보고(보는 동안 새 캔들이 생겨도 화면이 밀리지 않는다), 위아래로 가격 범위를 옮긴다(최대 차트 높이 하나만큼). 더블클릭하면 크기와 위치가 원래대로 돌아가고, 다른 종목을 고르면 위치만 원래대로 돌아간다. 최신 캔들을 볼 때는 높이를 키워도 현재가가 늘 화면 안에 있다. 과거 차트 없이 시작가에서 출발해, 게임 시작 직후부터 왼쪽 끝에서 캔들이 쌓인다(`timing.historyCandles` = 0). 시작 화면에서는 시세가 멈춰 있다.
- **거래량:** 변동성이 큰 종목일수록 거래량이 많다. 거래량이 많을수록 시세가 자주 바뀌고(킹카콜라 약 2초마다 … 게이임스탑 초당 10번), 주문이 늦게 체결된다(킹카콜라 즉시 … 게이임스탑 0.4~1초 뒤 그때 가격). 거래량이 적을수록 차트의 세로 범위를 넓게 잡아 캔들이 짧게 보인다(`volume.chartPad`: 적음 2.6 · 보통 2 · 많음 1.5 · 매우 많음 1.2 · 폭발 1.12배). 시세 자체는 바뀌지 않는다.
- **차트 모양:** 쐐기·삼각형·박스권·헤드앤숄더·컵앤핸들·깃발·쌍봉과 버블 사이클이 번갈아 그려진다. 모양은 무작위로 뒤집히고 돌파 방향도 무작위라서 추세를 바꾸지 않고 아무것도 예고하지 않는다.
- **급등·급락:** 종목마다 **2분에 한 번** 일어날 수 있다. 2분 구간 안의 아무 때나 일어나므로 1:50에 터지고 2:05에 또 터질 수도 있다. 0.1~0.4초 만에 끝나서 클릭으로 올라탈 수 없다.
- **경향 = 움직임의 모양:** 인버스가 있고 장 마감도 없으므로, 어느 종목이든 **기대 가격은 제자리**다(오르는 쪽에도 내리는 쪽에도 공짜 돈이 없다). 경향은 모양으로 나타난다. 킹카콜라·SK로우닉스는 대부분 서서히 오르다 가끔 크게 빠지고(5분 뒤 오른 비율 58% · 64%), 뭐더나는 대부분 흘러내리다 가끔 크게 솟는다(5분 뒤 내린 비율 67%). 지난 10초·30초의 방향이 다음에 이어질 확률은 약 50%(동전 던지기)다.
- **돈:** 기본예탁금 **$1,000**로 시작. **매수**(오르면 이익)나 **인버스**(내리면 이익)를 할 때 증거금(투자 금액)과 레버리지(1·2·5·10배, 모든 종목 같음)를 고른다. 레버리지는 평가 자산 $2,000부터. 수수료는 주문 규모(증거금 × 레버리지)의 0.1%를 살 때·팔 때 각각 낸다.
- **청산:** 손실이 증거금의 80%에 닿으면 강제청산되고 증거금을 모두 잃는다. 1배 매수는 청산되지 않는다(가격이 0 밑으로 가지 않으므로). 인버스는 가격이 오르는 만큼 손실이 끝없이 커지므로 1배도 청산된다. 예탁금이 음수가 되는 일은 없다.
- **끝:** **장 마감이 없다.** 원할 때 [정산하기]로 끝낸다(체결을 기다리던 주문은 취소, 보유 종목은 현재가로 매도). 보유 종목이 없고 예탁금이 최소 주문($10 + 수수료)보다 적으면 파산으로 끝난다. **평가 자산이 $50,000을 넘으면**(`economy.autoSettleAt`) 그 순간 전부 매도하고 끝난다(자동 정산, 야바위의 50칩과 같은 기준).

## 1. 운영 흐름

1. **시작 화면:** 규칙 요약과 [게임 시작](Enter). 시세는 멈춰 있다.
2. **게임:** [게임 시작]을 누르면 새 계좌($1,000)로 시작하고, 시작 화면의 멈춰 있던 새 시장(모든 종목이 시작가)이 움직이기 시작한다. 상단 시계는 **경과 시간**이다.
3. **거래:** 좌측 탭(또는 ↑↓ 키)으로 종목을 고르고, 우측에서 매수 · 인버스 · 매도한다. 한 종목에는 한 방향만 보유할 수 있다(매수를 들고 있으면 먼저 매도해야 인버스를 살 수 있다). 체결이 늦는 종목은 "주문 접수" 알림 뒤 버튼이 "체결 중…"으로 바뀌고, 체결되면 그때 가격으로 결과가 뜬다. 상세 설명 아래에는 거래량만 나온다(시세 갱신 빈도와 체결 시간은 화면에 쓰지 않는다).
4. **정산:** 상단 [정산하기] → 확인, 또는 평가 자산 $50,000 초과("$50,000 돌파! 자동 정산") → 결과 화면(최종 금액, 손익, **칩 환산**, 플레이 시간, 거래 횟수, 강제청산 횟수, 낸 수수료) → [처음으로](Enter).

## 2. 종목과 차트 모델

모든 종목이 같은 0.1초 틱으로 움직인다. 매 틱 종목의 **실제 가격**(로그)이 아래를 더한 만큼 바뀐다. 화면에 보이고 거래되는 **시세**는 그 종목이 거래될 때만 실제 가격을 따라잡는다(거래량). 캔들은 시세로 만들고, 고가·저가는 그 3초 안의 시세 중 최고·최저다. 종목마다 시작가 대비 가격 범위(`bounds`)를 벗어나면 서서히 끌어당기고, 시작가의 1%~100배는 절대 넘지 않는다.

**어느 부분도 기대 가격을 움직이지 않는다.** 인버스가 생기면 "떨어지는 종목에 인버스", 장 마감이 없으면 "오르는 종목을 오래 들고 있기"가 공짜 돈이 되기 때문이다(4장 밸런스 메모).

1. **잡음** (`noise`): 가우스 잡음인데 그 크기가 잔잔한 구간과 출렁이는 구간을 오간다(평균 분산은 `vol²`로 고정). 가끔 위아래 같은 확률의 점프가 섞인다. 게이임스탑은 0.1~0.3초 만에 되돌아오는 바늘이 더해진다. 로그 가격의 잡음은 그대로 두면 평균 가격을 조금 올리므로(볼록성) 그만큼 빼 준다.
2. **파동** (`wave`, 돌지코인만): 길이와 높이가 반 파동마다 바뀌는 사인파 두 개가, 천천히 떠도는 기준선 주위를 오간다.
3. **차트 모양** (`patterns`, `src/game/patterns.ts`): 아래 모양을 차례로 그리고 사이사이 평범한 구간을 둔다. 모양은 꼭짓점 목록이고 가격은 그 사이를 직선으로 따라간다(잡음은 그 위에 얹힌다). 꼭짓점 높이는 ±15% 흔들리고, 4번 중 1번은 덜 완성된 채 돌파한다. 크기는 60초짜리 모양 기준이며 길이의 제곱근에 비례한다.
   - 쐐기(상승·하락), 대칭 삼각형, 박스권(상승·하락 직사각형), 헤드앤숄더(역·정), 컵앤핸들(정·역), 삼각형(상승·하락), 깃발(정·역), 쌍봉·쌍바닥: 반은 뒤집혀 나오고 돌파 방향은 동전 던지기라서, 모양이 돌파 방향을 알려 주지 않고 평균적으로 가격을 옮기지 않는다.
   - 버블 사이클: 스텔스 → 1차 하락 → 언론·대중 참여 → 열정·탐욕·환상 → 정점 → 현실 부정 → 공포·투매 → 좌절(시작보다 아래) → 정상화(시작 가격으로). 2~4분짜리이고 끝나면 제자리다.
4. **급등·급락** (`events`, `src/game/events.ts`): 게임 시작부터 2분(`timing.eventWindowSec`)씩 끊어, 구간마다 `chance` 확률로 한 번, 구간 안의 아무 때나 일어난다. 0.1~0.4초 만에 끝나고 뒤따르는 반납이나 미끼는 없다. **그 구간의 이벤트가 아직 안 왔으면** 가격은 이벤트의 기대 효과만큼 반대로 흐른다: 급락만 있는 종목은 서서히 오르고, 급등만 있는 종목은 서서히 흘러내린다. 이것이 종목의 경향이다. 흐르는 양은 "이번 틱에 터질 확률 × 터졌을 때 평균 가격 변화"라서, 구간 끝이 가까워질수록 조금씩 커지고 이벤트가 터지면 다음 구간까지 멈춘다. 그래서 이벤트를 기다리든, 터진 뒤에 들어가든, 2분 구간의 어느 시점을 노리든 기대 가격은 그대로다.

| 탭 | 종목 (티커) | 시작가 | 난이도 | 거래량 · 시세 갱신 · 체결 | 잡음 | 차트 모양 크기 · 버블 | 급등·급락 (2분마다) | 이벤트 전 흐름 |
|---|---|---|---|---|---|---|---|---|
| 1 | 킹카콜라 (KKCL) | $64 | ★ 쉬움 | ▮ 적음 · 약 2초마다 · 즉시 | 0.1%/√초 | 0.8% · 없음 | 15% · 급락 −6~10% | 분당 +0.6% |
| 2 | SK로우닉스 (SKLW) | $140 | ★★ 보통 | ▮▮▮ 많음 · 초당 약 2번 · 0.2~0.5초 | 0.3%/√초 | 2% · 5%(정점 +13%) | 7% · 급락 −24~32% | 분당 +1.0% |
| 3 | 돌지코인 (DOLGE) | $2 | ★★★ 어려움 | ▮▮▮▮ 매우 많음 · 초당 약 3번 · 0.3~0.7초 | 0.8%/√초 + 파동 | 4.5% · 10%(정점 +16%) | 45% · 반반으로 ±5~10% | 거의 0 |
| 4 | 뭐더나 (MWDN) | $61 | ★★★★ 고난도 | ▮▮ 보통 · 약 1초마다 · 0.1~0.3초 | 0.4%/√초 | 2.2% · 없음 | 15% · 급등 +22~57% | 분당 −2.9% |
| 5 | 게이임스탑 (GGME) | $10 | ★★★★★ 극악 | ▮▮▮▮▮ 폭발 · 초당 10번 · 0.4~1초 | 2%/√초 + 바늘 | 6% · 5%(정점 +49%) | 60% · 반반으로 +22~57% 또는 −22~42% | 분당 −0.9% |

**레버리지 한도 없음:** 모든 종목이 1·2·5·10배를 연다. 대가가 있다. 급등·급락 한 번이 청산가를 훌쩍 넘어 버리면 손실은 증거금에서 멈추는데, 그동안 흐름으로 번 이익은 레버리지만큼 커진다. 그래서 "2배를 만든 뒤 SK로우닉스 10배 매수"와 "뭐더나 10배 인버스"를 들고 버티면 평균이 1배를 넘는다(4장 B표: 30분 평균 1.54~1.61배, 10배 도달 7~9%. $50,000 자동 정산은 이 수치를 거의 바꾸지 않는다).

난이도는 결과가 얼마나 거친가(5분 p5 ~ p95 폭: 킹카콜라 −10%~+8% … 게이임스탑 −72%~+135%) 순서다.

## 3. 계좌 규칙 (`src/game/account.ts`)

| 항목 | 값 |
|---|---|
| 기본예탁금 | $1,000 (`economy.deposit`) |
| 방향 | **매수**(오르면 이익)와 **인버스**(내리면 이익). 종목마다 한 방향의 포지션 하나(격리 증거금). 반대 방향을 사려면 먼저 매도한다. |
| 레버리지 | 1·2·5·10배 (`economy.leverages`), 모든 종목 같음. 2배 이상은 평가 자산 $2,000부터(기본예탁금의 2배)(`economy.leverageFrom`). 그 아래로 떨어지면 1배만 새로 살 수 있고, 이미 보유한 레버리지 포지션은 유지된다. |
| 주문 | 증거금 $10 이상(`economy.minOrder`). 증거금 + 수수료가 예탁금 이하일 때만. |
| 체결 | 종목의 `volume.fillDelay`만큼 기다렸다가 **그때 시세**로 체결한다. 킹카콜라는 즉시(보이는 가격). 체결을 기다리는 동안 그 종목에는 새 주문을 낼 수 없고, 체결 때 조건(예탁금, 레버리지 해금, 방향)을 다시 확인한다. |
| 수수료 | 주문 규모의 0.1%(`economy.feeRate`), 살 때·팔 때 각각, 1센트 단위로 올림 |
| 추가 매수 | 같은 방향·같은 레버리지만 가능하고 평단은 가중평균. |
| 청산가 | 매수 `평단 × (1 − 0.8 / 레버리지)`, 인버스 `평단 × (1 + 0.8 / 레버리지)` (`economy.maintenance` = 0.2). 매수 2배 −40%, 5배 −16%, 10배 −8%; 인버스 1배 +80%, 2배 +40%, 10배 +8%. 닿으면 남은 20%까지 모두 잃는다. **1배 매수는 청산 없음.** |
| 매도 | 25·50·75·100%. 받는 돈 = 증거금 × 비율 + 손익 − 수수료(0 미만이면 0). 인버스의 손익은 `수량 × (평단 − 현재가)`. |
| 게임 시간 | 제한 없음. [정산하기]로 끝낸다. |
| 칩 환산 | $1,000 = 1칩(`economy.chipValue`, 야바위와 같은 칩), **최대 50칩**(`economy.maxChips`). 결과 화면에 최종 금액 ÷ 1,000을 소수점 버림으로 보여 준다(기본예탁금 $1,000 = 1칩). 급등으로 $50,000을 크게 넘어 끝나도 지급은 50칩. |
| 자동 정산 | 평가 자산이 $50,000(50칩)을 넘으면 매 틱(0.1초) 확인해 바로 전부 매도하고 끝낸다. 체결을 기다리던 주문은 취소. 시뮬레이션 봇도 같은 규칙으로 멈춘다. |

**꼼수 방지**
- 가격은 `crypto.getRandomValues`로 만든다. 다음 움직임을 미리 알 방법이 없다.
- 모든 종목의 기대 가격이 제자리라서, 매수든 인버스든 "들고 기다리기"로 돈을 벌 수 없다. 오래 할수록 수수료와 청산만큼 줄어든다(4장 B표 30분 열).
- 급등·급락은 0.1~0.4초 만에 끝나고 뒤따르는 반납이 없다. 이벤트 전의 흐름은 이벤트가 터지면 멈춘다. 그래서 "급등 뒤 인버스", "급락 뒤 매수", "이벤트가 지난 구간에서만 보유" 모두 평균 1배다(4장).
- 차트 모양과 버블에 기대 이익이 생기는 규칙을 두지 않는다. 추세 추종, 반대 매매, 박스권 매매, 꼭대기 인버스 봇이 양방향으로 해도 이기지 못하는 것을 확인했다(4장).
- 거래량이 많은 종목은 체결이 0.2~1초 늦다. 화면에서 본 꼬리(바늘)나 순간 가격을 노려서 사고팔 수 없다.
- 시장은 절대 멈추지 않는다. 정산 확인 창이 떠 있어도 틱, 체결, 강제청산이 계속된다.
- 매 틱 가격을 바꾼 직후 강제청산을 먼저 처리한다. 청산가를 넘은 가격에 팔 수 없다.
- 수수료는 올림이라 주문을 잘게 나눠도 싸지지 않는다. 증거금 입력은 숫자만 받고 센트 단위로 자른다.
- exe에서는 새로고침(F5, Ctrl+R), 개발자 도구, 확대/축소 키를 막는다. 차트 위의 휠과 Ctrl+휠(페이지 확대)은 막는다. 게임 상태는 저장하지 않으므로 창을 닫으면 그 게임은 끝난다.

**목표**
- 어떤 전략도 평균 1배를 넘지 않는다(매수·인버스 양쪽, 어느 시간에 정산하든). 표본 오차는 ±0.03배 안팎이다.
- 몇 초~몇십 초 앞은 동전 던지기(방향 지속 50% 안팎), 종목 경향은 5분 동안 드러남.
- 2배 이상: 가장 잘 노려도 30분에 약 20%.

- **왜 모든 종목의 기대 가격을 제자리로 했나:** 3차 모델(뭐더나 5분 평균 −5%, 킹카콜라 +4%)에 인버스를 붙이고 마감을 없애면 이렇게 된다(같은 봇, 200게임). 뭐더나 인버스를 들고 있기만 해도 15분 뒤 84%가 이익이고 30분에 1.32배다. 킹카콜라 매수는 30분 1.26배, SK로우닉스 매수는 1.41배다. 급등 뒤 20초 인버스(뭐더나 급등 후 반납을 노림)는 30분 1.42배다. 2배 후 SK로우닉스 10배 존버는 30분에 평균 1.86배가 되고 13.5%가 10배에 닿는다. 경향을 "평균적으로 오른다"가 아니라 "대부분 오르고 가끔 크게 빠진다"로 바꿔 이 꼼수를 모두 없앴다.
- **경향의 크기:** 기대 가격이 제자리이면 "5분 뒤 오를 확률"은 급락이 드물고 클수록, 잡음이 작을수록 높아진다. 급락을 크게 하면 고배율에서 청산이 손실을 막아 줘서 평균이 1배를 넘는다(2장, 레버리지 한도 없음). 킹카콜라는 급락이 −8% 안팎이라 5분 오른 비율이 58%이고, SK로우닉스는 급락이 −28%라 64%다.
- **돌지코인 버블:** 버블은 오르는 구간과 꺼지는 구간이 길고 일정해서, 인버스가 생기면 추세 추종이 양쪽을 다 먹는다(돌지코인만 노리는 추세 추종, 버블 10% · 정점 +35%에서 30분 1.4배). 정점을 +16%로 낮춰 추세 추종 0.96배, 반대 매매 0.82배로 만들었다.
- **장 마감이 없을 때의 꼬리:** 공정한 게임에서도 오래 할수록 운이 좋은 소수의 결과가 커진다. 게이임스탑을 1배로 들고만 있어도 30분 뒤 0.9%가 10배다. 끝까지 버티면 이론상 "10배에 닿을 확률"은 최대 1/10까지 오를 수 있다(평균이 1배이므로). 수수료·청산이 그보다 낮추지만, 축제에서 한 사람의 플레이 시간을 제한하고 싶으면 운영으로 정한다.
- **차트 모양의 크기:** 클수록 눈에 잘 보이지만 박스권·반대 매매에 이득이 생긴다. 양방향 봇이 1배를 넘지 않는 크기로 맞췄다.

## 5. 아키텍처

**Stack:** Vite + TypeScript (vanilla DOM, Canvas 2D), Vitest, Playwright, Electron(portable exe). Runtime dependencies: none.

```
src/
  main.ts            boot
  config.ts          모든 조정값과 타입 (scripts/simulate.ts도 같은 파일을 읽음)
  rng.ts             crypto RNG, seeded RNG(테스트·시뮬레이션), gauss, meanExp
  game/market.ts     Market: 틱마다 잡음 + 파동 + 차트 모양 + 급등·급락, 거래량에 따른 시세, 캔들    (pure)
  game/patterns.ts   차트 모양 목록(쐐기, 삼각형, 박스권, 헤드앤숄더, 컵앤핸들, 깃발, 쌍봉, 버블)과 재생  (pure)
  game/events.ts     2분 구간마다 한 번의 급등·급락과 그 전의 흐름                                      (pure)
  game/account.ts    매수, 인버스, 매도, 강제청산, 평가금액                                             (pure)
  audio.ts           Web Audio 효과음 (매수, 매도, 수익, 손실, 강제청산 …)
  ui/app.ts          화면 배치와 게임 흐름, 0.1초 틱 루프, 체결 대기 주문
  ui/chart.ts        캔버스 캔들 차트 (왼쪽 끌기: 캔들 폭·높이, 오른쪽 끌기: 화면 이동, 평단·청산가 선)
  ui/format.ts, dom.ts, style.css
tests/unit/{account,market,events}.test.ts
tests/e2e/smoke.spec.ts
scripts/simulate.ts  차트 통계 + 플레이어 봇 (4장 표)
electron/main.cjs
```

## 6. 명령

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치 (Electron 포함) |
| `npm run dev` | 브라우저 개발 서버 |
| `npm test` / `npm run e2e` | 단위 테스트 / 화면 테스트 |
| `npm run sim [게임 수] [분]` | 4장 표 다시 계산 (기본 1000게임 × 30분, 약 3~4분 걸림) |
| `npm run app` | 빌드 후 Electron 창으로 실행 |
| `npm run exe` | Windows portable exe 만들기 (`release/YeongkkeulMoonS-0.2.0-portable.exe`). Linux에서도 wine 없이 만들어진다. |
