# 카지노 플랫폼 설계서

> 대상: 축제 운영진. 관리자 PC 1대(장부 서버)와 플레이어 PC 여러 대가 **같은 와이파이**에 있다. 통화는 **칩**(정수)이다.
> 이번 단계는 **장부·서버 핵심**이다: 장부, 관리자 화면, 플레이어 화면(로그인·잔고·정산 요청). 게임(야바위, 영끌문S)을 칩에 연결하는 일은 다음 단계이고, 그때 쓸 규약은 이미 서버에 들어 있다(9장).
> 클라이언트 해킹은 대비하지 않는다. 대신 버그, 꼼수, 네트워크 끊김·정전 같은 예외를 막는다.

## 0. 한눈에 보기

- **구성:** 관리자 PC에서 **장부 서버**(`CasinoLedger` exe 또는 `npm start`)를 켠다. 같은 서버가 관리자 화면과 플레이어 화면을 함께 내보낸다. 플레이어 PC는 브라우저(크롬·엣지)로 서버 주소에 접속하면 되고, 따로 설치할 것이 없다.
- **플레이어 화면:** 처음 켜면 **로그인 / 가입하기**. 가입은 이름 + PIN(숫자 4자리)이고, 가입하면 **5칩**을 받는다. 로그인하면 게임들이 앱처럼 타일로 뜨고(이번 단계에서는 "연결 준비 중"), **잔고는 늘 화면 위에 보인다**. 원하는 칩 개수를 적어 **정산 요청**(실물 칩 교환)을 보낼 수 있다. 게임에서 칩을 다 잃으면 **자동으로 파산 신청**이 들어간다.
- **관리자 화면:** 모든 플레이어가 실시간으로 보인다: 온라인/오프라인 · 이름 · PIN · 잔고 · 가입 시각 · 최근 활동 · 접속 시간. 플레이어마다 **수정**(이름·PIN·잔고만), **정산**(실물 칩 교환), **삭제**(확인 창). 오른쪽 "처리할 일"에 정산 요청, 파산 신청, 진행 중인 게임이 뜬다. **DB 기록** 탭에 모든 수정·삭제·정산이 남고 CSV로 저장할 수 있다.
- **장부:** 칩이 움직일 때마다 한 줄씩 덧붙이는 파일 하나(`journal.jsonl`)다. 한 줄을 디스크에 확실히 쓴 뒤에 대답하므로, 대답을 받은 요청은 정전이 나도 사라지지 않는다. 서버를 다시 켜면 처음부터 다시 읽어 그대로 이어진다.

## 1. 운영 흐름

1. **서버 켜기 (관리자 PC):** `CasinoLedger-0.1.0-portable.exe`를 실행한다. 처음 실행할 때 Windows 방화벽 창이 뜨면 **"개인 네트워크" 허용**을 누른다(안 하면 플레이어 PC가 접속하지 못한다). 관리자 화면 오른쪽 위의 **플레이어 접속 주소**(예: `http://192.168.0.12:7777/`)를 확인한다.
2. **플레이어 PC:** 브라우저 주소창에 그 주소를 넣는다. 가입하거나 로그인한다. 다른 PC에서 같은 계정으로 로그인하면 앞의 PC는 로그인 화면으로 돌아간다(부스를 옮겨 다니는 손님용).
3. **정산 (실물 칩 교환):**
   - 플레이어가 요청하면 관리자 화면 "처리할 일"에 카드가 뜨고 소리가 난다. 카드에 PIN, 가입 시각, 게임 이력이 있다.
   - 본인 확인(PIN을 물어본다) → **[지급 확정]** → "확정!"이 뜬 **뒤에** 실물 칩을 건넨다. 순서가 반대면 꼼수가 된다(6장).
   - 손님이 카운터에 바로 온 경우: 플레이어 표의 **[정산]**으로 개수를 넣고 확정한 뒤 건넨다.
4. **파산:** 게임에서 칩을 다 잃어 잔고가 0칩이 되면 자동으로 파산 신청이 들어온다. 관리자는 손님을 보고 **[처리 완료]**를 누른다. 칩을 다시 주려면 [수정]에서 잔고를 바꾸면 되고, 잔고가 생기면 파산은 저절로 풀린다.
5. **하루 마감:** 위쪽 숫자 **잔고 합계**는 플레이어들에게 아직 남아 있는 칩, **지급한 실물 칩**은 오늘 내준 실물 칩이다. 실제 칩 통과 맞춰 보고, DB 기록 탭의 **CSV 내보내기**로 기록을 저장한다.
6. **서버 끄기:** 관리자 창을 닫으면 확인을 한 번 묻고 끈다. 장부는 매번 저장되어 있으므로, 다시 켜면 플레이어 화면도 자동으로 다시 연결된다(다시 로그인할 필요 없음).

## 2. 칩 장부 규칙 (`src/server/ledger.ts`)

**칩의 세 자리.** 플레이어의 칩은 **사용 가능**, **정산 대기**(요청한 뒤 관리자가 지급하기 전), **게임 중**(게임에 맡긴 칩) 중 한 곳에 있다. 세 자리의 합이 **잔고**이고, 플레이어 화면의 큰 숫자와 관리자 표의 "잔고"가 이것이다. 어느 자리도 0 아래로 내려가지 않는다.

| 일 | 누가 | 잔고 | 사용 가능 | 비고 |
|---|---|---|---|---|
| 가입 | 플레이어 | +5 | +5 | `PLATFORM.signupBonus` |
| 정산 요청 N | 플레이어 | 그대로 | −N (정산 대기 +N) | 한 번에 하나. 사용 가능한 칩까지만 |
| 정산 요청 취소 / 거절 | 플레이어 / 관리자 | 그대로 | +N | |
| 지급 확정 | 관리자 | −N | 그대로 | 정산 대기에서 빠진다 |
| 관리자 정산 N | 관리자 | −N | −N | 요청 없이 바로 |
| 수정 (잔고 → M) | 관리자 | → M | 차이만큼 | 정산 대기·게임 중 칩보다 작게는 못 한다 |
| 삭제 | 관리자 | 전부 사라짐 | — | 정산 대기·게임 중 칩 포함 |
| 게임 입장 (판돈 S) | 게임 | 그대로 | −S (게임 중 +S) | 9장 |
| 게임 정산 (결과 P) | 게임 | +P − S | +P | 결과가 0이고 다른 칩이 없으면 자동 파산 신청 |
| 게임 강제 종료 | 관리자 | +P − S | +P | 결과를 보내지 못하는 게임(PC 고장)을 환불·몰수·직접 입력으로 닫는다 |

- **검산:** 언제나 `잔고 합계 = 가입 보너스 + 관리자 수정 + 게임 손익 − 지급한 실물 칩 − 삭제된 계정`이다. 단위 테스트가 무작위 2,000번 조작 내내 이 식을 확인한다.
- **이름:** 1~12글자. 대소문자와 띄어쓰기만 다른 이름은 같은 사람으로 본다("Kim Lee" = "kim lee"). **PIN:** 숫자 4자리.
- **수정의 버전:** 관리자 수정은 관리자가 보고 있던 "버전"을 함께 보낸다. 창을 연 사이에 플레이어의 칩이 움직였으면 거절하고 지금 값을 보여 준다. 관리자가 모르는 변화를 덮어쓰지 않는다.
- **DB 기록:** 가입, 수정(바뀐 값 전후), 삭제(그때의 잔고와 계정 정보), 정산 요청·취소·거절·지급 확정·관리자 정산, 파산 신청·처리, 게임 강제 종료가 남는다. 게임 입장·정산은 "전체" 보기에서만 보인다. 각 줄에 그때의 이름, 잔고 변화, 그 뒤의 잔고가 있다. 기록은 장부 파일 그 자체에서 나오므로 따로 지워지거나 어긋나지 않는다.

## 3. 장부 파일과 장애 (`src/server/journal.ts`, `store.ts`)

- **파일:** `카지노장부-data/journal.jsonl`(exe 옆 폴더) 또는 `플랫폼/data/journal.jsonl`(`npm start`). 한 줄이 한 사건이다. **한 명령 = 한 줄**이라서 정전이 나도 명령이 반쯤 반영되는 일이 없다.
- **쓰기:** 줄을 덧붙이고 디스크에 강제로 쓴(fsync) 다음에 대답한다.
- **다시 켤 때:** 파일 전체를 처음부터 다시 적용한다(축제 하루 수천 줄은 순식간이다).
  - 마지막 줄이 정전으로 잘려 있으면 버린다. 그 요청은 대답을 못 받았으므로 플레이어 화면이 다시 보낸다.
  - 중간 줄이 망가져 있으면 **서버가 켜지지 않는다**. 구멍 난 장부를 믿지 않기 위해서다. `backups` 폴더의 사본으로 바꾼다.
- **백업:** 켤 때마다 `backups/journal-<시각>.jsonl`로 복사한다(최근 30개). 복구는 사본을 `journal.jsonl`로 이름을 바꿔 넣으면 된다.
- **이중 실행 방지:** 같은 장부를 쓰는 서버가 이미 있으면 `server.lock`이 막는다(두 서버가 같은 파일에 쓰면 섞인다). exe는 한 PC에 하나만 뜬다. 강제 종료로 남은 잠금은 다음 실행이 넘겨받는다.
- **시계:** PC 시계를 뒤로 돌려도 기록 시각은 뒤로 가지 않는다.

## 4. 통신 (`src/server/server.ts`, `src/shared/protocol.ts`)

HTTP + JSON. 실시간 알림은 server-sent events(브라우저의 `EventSource`가 끊기면 스스로 다시 연결한다). 패키지 없이 Node 기본 모듈만 쓴다. 포트 **7777**.

| 경로 | 누가 | 하는 일 |
|---|---|---|
| `POST /api/signup` `{name, pin, key}` | 플레이어 | 가입 → `{token, me}` |
| `POST /api/login` `{name, pin, key}` | 플레이어 | 로그인 → `{token, me}`. 다른 PC의 이전 로그인은 끝난다 |
| `POST /api/logout` | 플레이어 | |
| `GET /api/me`, `POST /api/ping` | 플레이어 | 지금 상태. ping은 5초마다 보내는 "접속 중" 신호 |
| `GET /api/events?token=` | 플레이어 | 실시간: `me`(잔고 등이 바뀔 때), `kicked`(다른 PC 로그인, 계정 삭제) |
| `POST /api/settle` `{amount, key}` · `/api/settle/cancel` `{id}` | 플레이어 | 정산 요청 · 취소 |
| `POST /api/game/open` `{game, stake, key}` | 게임 | 판돈을 맡기고 게임 시작 → 세션 `{id, secret}` |
| `POST /api/game/close` `{id, secret, payout}` | 게임 | 결과 보고. 로그인 없이 `secret`만으로 된다 |
| `GET /admin`, `/api/admin/*` | **관리자 PC에서만** | 화면, 실시간 상태(`/api/admin/events`), 수정·삭제·정산·지급 확정·거절·파산 처리·게임 강제 종료, `log.csv` |

- **온라인:** 플레이어 화면이 5초마다 신호를 보내고, 15초 동안 신호가 없으면 오프라인이다. 연결이 열려 있는 것만으로는 판단하지 않는다(와이파이 밖으로 나간 노트북은 연결이 몇 분씩 열려 있는 것처럼 보인다).
- **접속 시간:** 온라인인 동안 쌓이고, 오프라인이 될 때와 5분마다 장부에 저장한다.
- **관리자 전용:** 관리자 화면과 관리자 API는 서버가 돌고 있는 PC 자신(localhost 또는 그 PC의 주소)에서 온 요청만 받는다. 플레이어 PC에서 `/admin`을 열면 거절된다.
- **토큰:** 로그인마다 새 비밀값을 만들고 장부에 적는다. 서버를 다시 켜도 로그인이 유지되고, 새 로그인이 생기면 이전 토큰은 그 즉시 쓸 수 없다.

## 5. 예외 처리

| 상황 | 일어나는 일 |
|---|---|
| 플레이어 PC 와이파이가 끊김 | 플레이어 화면 위에 빨간 띠 "연결이 끊겼습니다 · 다시 연결하는 중…". 칩이 움직이는 버튼(정산 요청·취소)은 잠긴다. 관리자 화면에서는 15초 안에 오프라인이 된다. 돌아오면 저절로 다시 연결되고 최신 잔고를 받는다. |
| 요청을 보낸 순간 끊김 | 같은 요청을 같은 `key`로 최대 30초 다시 보낸다. 서버는 같은 key에 처음 대답을 돌려주므로, 대답만 잃어버린 경우에도 정산 요청이 두 번 들어가지 않는다. |
| 서버(관리자 PC)가 꺼짐·재시작 | 플레이어 화면은 빨간 띠를 띄우고 2초마다 다시 연결한다. 켜지면 로그인을 유지한 채 이어진다. 관리자 화면도 같다. |
| 정전 | 대답을 보낸 것은 모두 디스크에 있다. 잘린 마지막 줄은 버린다(3장). |
| 관리자가 버튼을 두 번 누름 | 지급 확정·거절·파산 처리는 서버가 "이미 처리됨"으로 막는다. 관리자 정산은 창마다 key가 하나라 두 번 빠지지 않는다. 처리한 카드는 바로 사라진다. |
| 관리자 화면이 낡은 값을 보고 수정 | 버전이 달라 거절되고, 지금 값이 보인다(2장). |
| 게임 PC가 게임 도중 고장 | 맡긴 칩은 "게임 중"으로 남아 관리자 "처리할 일"에 뜬다. 관리자가 환불·몰수·직접 입력으로 닫는다. |
| 같은 계정으로 다른 PC 로그인 | 앞의 PC는 "다른 PC에서 같은 계정으로 로그인했습니다"와 함께 로그인 화면으로 돌아간다. 게임 결과는 세션 비밀값으로 보고하므로, 로그인이 끝나도 진행 중이던 게임의 칩은 돌아온다. |
| 계정 삭제 | 그 플레이어 화면은 "관리자가 계정을 삭제했습니다"와 함께 로그인 화면으로. |
| PIN을 계속 틀림 | 같은 이름으로 5번 틀리면 30초 동안 그 이름의 로그인을 막는다. |
| 서버를 두 번 켬 | 두 번째는 켜지지 않는다(잠금 파일·포트·exe 단일 실행). |

## 6. 꼼수 방지

- **정산 요청한 칩으로 게임하기:** 요청하는 순간 칩이 "정산 대기"로 묶여 쓸 수 없다.
- **칩을 받고 요청 취소하기:** 관리자는 **[지급 확정]을 먼저** 누르고 확정이 뜬 뒤에 칩을 건넨다. 확정된 요청은 취소할 수 없고, 취소된 요청은 확정할 수 없다(서버가 한 번에 하나씩 처리한다).
- **남의 이름으로 칩 받기:** 정산 카드와 확인 창에 PIN이 보인다. 건네기 전에 손님에게 PIN을 물어 확인한다.
- **진 게임을 없던 일로 하기:** 게임은 시작할 때 판돈을 서버에 맡긴다. 네트워크를 끊거나 창을 닫아도 판돈은 돌아오지 않는다(관리자 강제 종료만 가능).
- **이긴 결과를 두 번 받기:** 게임 결과는 세션마다 한 번만 받는다. 같은 결과를 다시 보내면 처음 대답이 돌아오고, 다른 결과는 "이미 정산된 게임"으로 거절한다.
- **결과 부풀리기 버그:** 게임 결과가 그 게임의 한도(`maxPayout`, 두 게임 모두 50칩 또는 판돈)를 넘으면 받지 않고, 세션은 관리자가 확인하도록 남는다.
- **관리자 실수:** 수정은 보던 값이 바뀌면 거절되고, 삭제는 확인 창을 거친다. 모든 수정·삭제·정산은 DB 기록에 전후 값과 함께 남는다.
- **가입 보너스 여러 번 받기(남은 위험):** 이름만 바꿔 여러 계정을 만들면 5칩씩 받을 수 있다. 정산은 반드시 관리자를 거치므로, 정산 카드의 "가입 N분 전 · 게임 0판"을 보고 판단한다. 막아야 할 정도면 "가입 보너스는 게임에서만 쓰고 정산은 못 함" 같은 규칙을 다음 단계에서 넣을 수 있다.

## 7. 아키텍처

**Stack:** Node 22 (TypeScript를 그대로 실행), Vite(두 화면), Vitest, Playwright, Electron(exe). 서버의 실행 시 의존성은 없다.

## 8. 명령

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치 |
| `npm start` | 화면을 빌드하고 서버를 켠다 (`data/` 폴더, 포트 7777). `npm run server -- --port 8000 --data D:\장부`처럼 바꿀 수 있다 |
| `npm test` / `npm run e2e` | 단위 테스트 / 화면 테스트 |
| `npm run exe` | 관리자 PC용 Windows portable exe (`release/CasinoLedger-0.1.0-portable.exe`). Linux에서도 wine 없이 만들어진다 |

**네트워크 준비:** 관리자 PC와 플레이어 PC가 같은 와이파이에 있어야 한다. 휴대폰 핫스팟이나 일부 공유기는 "AP 격리(기기 간 통신 차단)"가 켜져 있어 서로 접속이 안 된다. 그럴 때는 그 설정을 끄거나 다른 공유기를 쓴다. 관리자 PC의 IP가 바뀌면 접속 주소도 바뀌므로, 가능하면 공유기에서 관리자 PC IP를 고정한다.

## 9. 다음 단계: 게임 연결

서버 쪽 규약은 이미 있다(`/api/game/open`, `/api/game/close`, 단위 테스트 포함). 남은 일은 게임 쪽이다.

1. **실행:** 플레이어 화면의 게임 타일이 게임을 연다(같은 서버가 게임 파일도 내보내거나, 플레이어 PC의 클라이언트 exe에 게임을 넣는다).
2. **입장:** 게임이 판돈(가져갈 칩)을 정해 `game/open`을 보내고, 받은 세션 `{id, secret}`을 게임 저장소에 적는다. 이때부터 게임은 네트워크 없이 돈다.
3. **정산:** 게임이 끝나면 결과 칩으로 `game/close`를 보낸다. 실패하면 저장해 둔 결과를 다시 보낸다(같은 결과는 한 번만 반영된다). 창을 닫았다 다시 열어도 저장소에 남은 세션을 먼저 정산한다.
4. **칩 환산:**
   - 야바위: 지금 구조 그대로 칩. 입장 칩이 게임의 시작 칩이 되고, 지급 상한 50칩도 그대로.
   - 영끌문S: 화면은 달러 그대로, **$1,000 = 1칩**. 입장 칩 × $1,000이 기본예탁금이 되고, 끝날 때 평가 자산을 칩으로 바꾼다(지금 게임 코드의 규칙: 버림, 최대 50칩).
